## 四、已知缺陷

### P0 · 影响可玩

_（无）_

### P1 · 影响体验

1. **梦游机制未实装**（SYSTEM_DESIGN §6.5）。它是「踩空」结局的唯一入口；没做则一周目只有「弃婴」一种死法。
2. **甜醉只有视觉**，没有"坐标提示错误 / 图纸噪点"的功能惩罚。
3. **对话没有打字机效果**，长台词一次性刷出。
4. **石桥峡谷感不足**：悬崖瓦片（`h`）俯视密排后仍偏像石壁。
5. **NPC 辨识度不足**：列车上的"睡着的老人"复用玛尔塔行走图、"看报的先生"复用赫尔曼，看起来就是"站着的玛尔塔/赫尔曼"。需要专属行走图。
6. **赫尔曼 / 玛尔塔的立绘仍是程序化 96×96**，显示为 192×192 时是 2 倍放大，与 256 素材立绘的清晰度不一致。

### P2 · 打磨

7. 序章列车偏空的感觉已缓解（12 个交互点），但纯装饰仍少。
8. 走廊画像间距不均。
9. 成就「不对劲」需三处异常但无保底提示。
10. `local_docs` 里的大素材图不入库（`.gitignore`），换机器需手动拷。

## 五、工程约定（踩过的坑）

1. **不要用 `(?s)` 正则整块替换 `maps.ts` 的地图定义**——非贪婪在文件末尾会吃掉下一个定义。改用 `IndexOf` 锚点插入。
2. **同一块瓦片密排会变成另一种东西**（石地→墙、桌子→文件柜）。判断方法：给没看过设计的人看，问"这是哪里"。
3. **vite 的 fs watcher 会被 headless 浏览器的缓存目录撞崩**（EBUSY）。截图必须把 `--user-data-dir` 指到项目外。
4. **并行 agent 会撞坐标与文件**。集成时逐条核对跨文件的坐标、key、导出名。
5. **`=` 字符已被车厢壁占用**，原墓碑瓦片让位。陵园开工前先给墓碑分配新字符。
6. **放大行走图必须同步改碰撞盒**，且要实走窄走廊验证。
7. **文字规格能约束风格，约束不了形象**。要"像某个角色"，第一件事是要图。
