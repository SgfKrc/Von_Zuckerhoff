### 2.4 可复用的单章节拍模板

把两案叠在一起，得到一个 9 段模板（括号内是台词预算与实测值）：

```
S0 幕间/章节卡      2-4 条        ← 时间跳跃 + 一句「这一案的主题」引言
S1 入场            3-5 条        ← 主角复述「我知道该怎么做了」，等于把玩法教一遍
S2 门槛（守门人）   4-7 条        ← 挡住去路，逼玩家先看告示板，顺手给第一个线索
S3 两条证词并置    10-12 × 2 条   ← 故意矛盾，这是整章推理的引擎
S4 现场 + 医生     12-15 条       ← 给验尸结论，同时打开下一张地图的门
S5 取证圈          3-5 个点，每点 2-6 条  ← 3 个核心物证 + 1-2 个必须开眼睛的隐藏点
S6 集齐闸门        1-2 条         ← 只做一件事：告诉玩家「可以推理了」
S7 推理            3 题 / 每题 3 选 1
S8 转折独白        8-12 条        ← 复述结论 → 反派承认 → 传送 → 震动 → 开战
S9 胜利独白 + 钩子  8 条           ← 一句「这只是第一笔」，把下一案变成预告
```

实测台词重心（第一案 / 第二案）：S3（两条证词）+ S4（现场医生）+ S5（取证圈）三段合计 **44 条 / 66 条**，分别占该章台词的 **39% / 41%**。也就是说，**四成的文本都花在"收集矛盾"上**；S8 转折独白只有 8-12 条（7%-8%），但它是唯一一段没有交互、纯靠文本承重的段落。

两个模板级的硬约束：

1. **每章恰好 3 个核心线索来自"人"，2 个来自"物"。** 第一案：watchTalk / rosaTalk / autopsy 来自 NPC，flower / apron 来自现场。第二案：longTalk / cadoschTalk / autopsy2 来自 NPC，rings / coins 来自现场。这个 3:2 比例保证了"推理依靠证词，结论落在物证"。
2. **每章只开一扇新门，且都在本章前半段。** 第一案在 S2（告示板 → `caseOpen`，巷口警戒线撤掉），第二案在 S4（和医生谈完 → `morgueOpen`）。第一案的门是"许可"，第二案的门是"证据"——第二次开门时，玩家已经学过"和医生说话会得到新地图"这个因果关系。

**密度规律**：小案子现场密度最高，街道密度最低。

- 后院 21.9 格/点、巴克巷 28.8 格/点——**案发现场必须挤，挤才有压迫感**；
- 主街 54.6、画室 64.5、停尸间 48.0——**过渡空间必须空，空才走得动**。

这不是巧合：两张高密度图（yard、alley）的黑暗度也最高（0.55、0.58），低密度图（tavern 0.22、atelier 0.24）最亮。

### 3.2 连通图：一棵树，不是一张网

```
atelier ──(单向,门被锁:neverOpen)──► street
                                      ├──► tavern（10,2 ↔ 12,12）
                                      ├──► alley （25,12 ↔ 0,5 / 0,6）
                                      └──► hanbury（0,6,7 ↔ 29,6,7）
                                            ├──► yard （9,2 ↔ 11,10）
                                            └──► morgue（19,2 ↔ 11,11，需 morgueOpen）
```

来源：`maps.ts:41-43, 90-97, 145-147, 192-195, 241-246, 287-289, 327-329`。

- **主街是唯一枢纽**。去酒馆要过主街，回案发现场也要过主街。这让"回访"变成默认动作而不是负担。
- **画室是单向的**：`lockFlag: 'neverOpen'`（`maps.ts:42`），门永远打不开，提示语是「深夜的门纹丝不动。……好像有什么东西不想让我离开。」——用一个永不满足的条件做叙事，而不是隐藏出口。
- **四张室内/院子图的出口都在底边中点**（院子 11/22、停尸间 11/24、画室 13/26、酒馆 12/26），回到地图时永远面向 down，玩家本能地往上走。两张街道图则是侧边开口（巴克巷 0,5；汉伯里街 29,6），因为它们本来就是"横着走过去"的空间。

### 3.3 空间如何承担叙事

硬指标（代码层）：

- 对话框 `max-width: 720px`、字号 14px、行高 1.9（`styles.css:277-292`）→ 中文约 47 字/行，可视约 3.5 行（`min-height: 96px`）。

### 4.3 同一物件在不同 flag 下的 5 种写法

复访文本全部集中在 `events.ts:59-128` 的 `switch` 里，按复杂度分五档：

1. **三段式（处境 → 主叙事 → 复访）**
   ```ts
   case 'guardTalk':
     if (!F.caseOpen) run('guardFirst')        // 没看告示板：只挡路，4 条
     else if (!F.guardDone) run('guardTalk')   // 第一案中：给证词，7 条
     else run('guardAfter')                    // 复访：1 条
     break
   ```
   （`events.ts:69-73`）同一张脸，三种社会关系。

2. **二态（跑过 / 没跑过）**
   ```ts
   case 'longTalk': run(F.longDone ? 'longAfter' : 'longTalk'); break
   ```
   （`events.ts:107`）第二案绝大多数用这种最简形式。

3. **隐藏内容的二次读**
   ```ts
   case 'graffitiRead': run(F.hidden_graffiti1 ? 'graffitiAfter' : 'graffitiRead'); break
   ```
   （`events.ts:76`）第一次读扣 6 理智并留下红色字，第二次只给你一句「它只是几道已经干透的颜料」（`script.ts:220`）——**用文本否定第一次的恐惧**，这比重复吓人有效。

4. **前置拦截（不锁门，锁对话）**
   ```ts
   case 'corpseLook':
     if (!F.docDone) run('corpseBlocked')      // 医生一句话把人推开
     else if (F.sawCorpse) run('corpseAfter')  // 看过了
     else run('corpseLook')                    // 第一次：−6 理智
   ```
   （`events.ts:94-98`）玩家走到尸体前会被"请留步。……先跟我谈"挡回来（`script.ts:329`）。**用 NPC 的礼貌当锁，比红字提示自然**。

5. **物件消失 + 资源复访**
   - `hideFlag`：拿到花后 `flowersA` 从地图消失（`maps.ts:178`），拿到围裙后 `doc` 在战斗胜利后消失（`maps.ts:176`）。
   - `fireLook` 第一次给 +4 理智，第二次改成一句「炉火噼啪作响，火星向上飘，像倒放的雪。」（`events.ts:15-17`）——**只有一次收益的补给点，第二次变成纯氛围**。

### 5.2 CORE_CLUES：什么是"够推理"

```ts
export const CORE_CLUES: Record<CaseId, ClueId[]> = {
  1: ['flower', 'apron', 'autopsy', 'rosaTalk', 'watchTalk'],
  2: ['rings', 'coins', 'longTalk', 'cadoschTalk', 'autopsy2'],
  ...
}
```
（`clues.ts:157-164`）

判定逻辑（`store.ts:1083-1100`）：

```ts
const core = CORE_CLUES[after.caseNo] ?? []
if (!core.length) return
const done = core.every(c => after.clues.includes(c))     // 必须"全部集齐"
const readyFlag = after.caseNo === 1 ? 'cluesReady' : `cluesReady${after.caseNo}`
const deducedFlag = after.caseNo === 1 ? 'deduced' : `deduced${after.caseNo}`
if (done && !after.flags[readyFlag] && !after.flags[deducedFlag]) {
  set({ pendingScript: after.caseNo === 1 ? 'cluesReady' : `cluesReady${after.caseNo}` })
}
```

三点设计含义：

1. **判定是"固定集合全齐"，不是"任意 N 条"。** 好处是进度可预期（HUD 永远知道还差什么），坏处是没有多解性。
2. **集齐是"被动"触发的**：拿到最后一条线索的瞬间，自动播 `cluesReady` 一句独白 + toast（`script.ts:392-395`），玩家不需要回头找 NPC 交任务。
3. **隐藏线索完全不参与判定**：`truthLevel()` 只看 `MORIARTY_CLUES` / `CULT_CLUES`（`endings.ts:15-29`）。所以"看得多"不影响能不能推理，只影响结局层级。

**这套结构的本质**：主线的门是硬的（5 条全齐），支线的价值是软的（影响结局与成就）。新项目如果要做"多解推理"，要替换的正是 `core.every()` 这一行。

| --- | --- |

**三个关键手法**：

1. **`needClue` 会显示成选项后面的灰色小字**（`DeductionBoard.tsx:78-82`），例如「(格雷夫斯的证词)」。等于在正确选项上贴了一个"依据"标签——玩家不需要记住线索名，只需要判断"这条依据支不支持这个结论"。
2. **三个选项分别对应三种典型误解**：时间太早 / 时间刚好 / 时间太晚；凶手是流氓 / 是屠夫 / 是绅士。**诱饵不是随机编的，是"玩家真会想到的错答案"**。
3. **错误反馈比选项长一倍**，而且反馈里会给新信息（"罗莎说她三点半才离开酒馆，而巷子离酒馆只有几步路"）——答错也是一次教学，不是惩罚。

### 5.4 答错惩罚与"没有失败态"

```ts
} else {
  sfx('hurt')
  noteMistake()
  changeSan(-5)
  addToast('推理出现偏差…… 理智 −5', 'san')
  setFlash({ text: opt.flash, ok: false })
}
```
（`DeductionBoard.tsx:57-63`）

- 惩罚只有 **−5 理智**，不锁题、不倒退、可无限重试。理智的上下限是 0-100（`store.ts:402`），−5 意味着"答错 20 次才会死"，实际中不可能触发。
- 但答错会被记进 `dedMistakes`（`store.ts:933`），章末结算时如果 `dedMistakes === 0` 就给成就 `flawless`（`store.ts:614`，`achievements.ts:76-80`）。
- **所以推理的压力是"评价压力"，不是"死亡压力"**——它保护了叙事节奏（玩家永远不会卡在推理里），代价是推理段没有真正的紧张感。这一点在第 10 节展开。

### 5.5 玩家怎样把线索连成结论

流程是「**集齐 → 3 题 → 一段独白把证据串成故事**」，第三步才是真正的"推理演出"：

1. 集齐 → `cluesReady` 一句：「(白花、围裙、验尸记录、罗莎和格雷夫斯的证词——拼图齐了。)」（`script.ts:393`）
2. 3 题各给一句判词，构成三段论：**时间 → 手法 → 动机**。
3. `DEDUCTION_DONE[case]` 指向 `deduceDone`（`deduction.ts:284-290`），播 8-12 条独白把结论复述成人话：

> 「凶手：受过外科训练，伪装成体面的绅士；以包下白花为饵，让安亲自领他进巷。」
> 「在巡夜人两次提灯的十五分钟里，一刀，自左向右。然后——他蹲下来，把白花摆成一幅静物画，再留下"皮围裙"这多余的一笔，嫁祸给传闻。」
> （`script.ts:399-400`）

第二案的复述更长（12 条，326 字），结构完全一样：**先否定一个错误前提（"医生没有错，朗太太也没有错——错的是『一个人作案』这个前提"），再把三条线索并成一条因果链**（`script2.ts:369-374`）。

**可复用的结论**：推理段 = 3 个可判定的封闭问题 + 1 段 200-330 字的"判决书"独白。前者给玩家"参与感"，后者给玩家"理解感"。缺前者会变成看剧情，缺后者会变成做选择题。

### 6.3 意图预读

- 界面永远显示一行「下一手：{招式名}」或「下一手：???（可用「素描凝视」看穿）」（`BattleUI.tsx:22-25`）。
- `revealed` 的三种来源：
  1. **主动技能**：`gaze`（素描凝视）让理智 +4 并揭开意图（`store.ts:991-996`）。
  2. **第一案的隐藏线索**：拿到 `watch`（停在 3:47 的怀表）后，战斗一开始 `revealed` 就是 `true`，并且**每回合结束后自动保持**（`store.ts:940-945`、`store.ts:1044`）。
  3. 蓄势后必定接最重的一击——这不是随机，是可学习的节拍（`store.ts:383-389`）。

```ts
function nextIntent(enemyId: string, prev: number, charged: boolean): number {
  const def = ENEMIES[enemyId]
  // 蓄势之后必定接最重的一击
  if (charged) {
    const heavy = def.moves.findIndex(m => m.kind === 'slash' || m.kind === 'double')
    if (heavy >= 0) return heavy
  }
  let pick = def.pool[Math.floor(Math.random() * def.pool.length)]
  if (pick === prev && Math.random() < 0.5) pick = def.pool[Math.floor(Math.random() * def.pool.length)]
  return pick
}
```

**这是全篇最好的一个"探索回报"设计**：一个可选的、藏在阴沟里的隐藏线索，把 Boss 战从"猜招"变成"读谱"。玩家不需要看攻略，就能感觉到"上次那 5 点理智花得值"。

### 6.5 战斗在叙事中的位置：它是"作者的拒绝"

两场战斗的触发点完全同构，都写在推理独白的最后一条 `do` 里：

```ts
{ t: 'do', do: [
  { flag: ['deduced', true] },
  { teleport: { map: 'alley', x: 8, y: 4, dir: 'right' } },
  { shake: 20, sound: 'sting' },
  { battle: 'shade1' },
] }
```
（`script.ts:406-414`；第二案 `script2.ts:380-388` 同构）

顺序是**先传送、再震动、再开战**：玩家被"摆"到巷口，面朝右，然后被打。战斗因此有一个具体的空间位置，战斗背景也沿用巷墙剪影（`renderer.ts:699-713`），而不是切到一个抽象界面。

战斗的剧情解释分三层：

1. **敌人是什么**：不是凶手本人，是凶手在这一页画布上的投影。
   - 「雾凝成人形。高帽、提包、以及一片没有脸的黑。」（`enemies.ts:20`）
   - 「——它不是执笔的那只手。它是替执笔者看着钟的那双眼睛。」（`enemies.ts:44`）
2. **为什么打**：因为你看穿了构图。「看穿构图的观众，就不再是观众了。——上台来吧，小画家。」（`script.ts:405`）
3. **打输会怎样**：直接进坏结局，而且结局把"死"写成"成为模特"——
   「别动。就保持这个角度。你的脖颈的线条，比我想象的还要好。」（`endings.ts:90`）

所以战斗的功能不是"考验操作"，而是**叙事上的一个转折动作**：玩家推理正确 → 作者承认 → 把你从观众席拉上台 → 你必须用行动（而不是语言）证明自己不是"适合待在画里的人"。

### 7.4 音效的"克制"清单

全篇只有 12 个音效名（`audio.ts:1234-1273`），恐怖相关的只有 3 个：

| 音效 | 配方 | 用在哪 |
| --- | --- | --- |
| `blip` | E6 音，增益 0.075，时长 0.028 秒 | 每 3 个字一次 |
| `sting` | A4 锯齿下滑到 C2（0.75 秒）+ 520Hz 低通噪声 + 一声 thump | 全篇 **12 次**：`script.ts:47,197,214,289,368,382,411`；`script2.ts:238,262,331,356,385` |
| `hurt` | 700Hz 噪声 + A2 锯齿下滑 | 扣理智时 |

`sting` 全篇只响 **12 次**，平均每 25 条台词才响一次。其中 **9 次跟着"信息揭晓"**：积水人影（`script.ts:197`）、涂鸦（`214`、`382`）、镜子（`289`）、怀表（`368`）、栅栏刻痕（`script2.ts:238`）、密码信（`262`）、六瓣印记（`331`）、请柬（`356`）；另外 3 次是入画与两次开战前（`script.ts:47,411`、`script2.ts:385`）。恐怖音效服务的是"认知冲击"，不是"怪物出现"——全篇没有一次为"怪物从角落跳出来"配过音。

## 8. 叙事手法

### 8.1 梦境 / 入画

序章开场是一段 5 条台词的清醒梦：先听见声音（`script.ts:7`），再意识到自己在桌上睡着（`script.ts:9`），最后发现声音来自一幅画。入画的过程只写两句：

> 「雾从画框里涌出来,像终于涨过堤岸的河。」（`script.ts:48`）
> 「煤气灯一盏一盏亮起。鹅卵石在脚下变得冰冷而真实。」（`script.ts:50`）

**没有解释机制**（为什么能进去、能不能出来），只给了规则的一句自述：「画布困不住绘梦人」（`script.ts:98`）。留白让玩家自己接受设定。

### 8.2 闪回 / 时间跳跃

两案之间用一段 4 条的幕间跳过一周，且明说时间不可信：

> 「——雾都的时间不按人的规矩走。」
> 「巷子里的煤气灯灭了又亮。等玛德蕾娜再抬起头,日历上已经翻过了一个星期。」（`script2.ts:20-21`）

这段幕间同时干了三件事：跳过等待、把"预告素描"兑现、给玩家一个"这次我准备好了"的心理位置（`script2.ts:44`）。

### 8.3 不可靠叙述

全篇有三处"你看到的不是真的"，且都做成了**可选**：

1. **积水**：水面上站着高帽绅士 →「猛然回头——身后只有雾。只有雾。」（`script.ts:193-195`）
2. **镜子**：缎带变成湿红 →「镜中的她,先眨了眼。」（`script.ts:286-288`）
3. **涂鸦**：只有开眼才看得见的红字「他 在 画 你」（`script.ts:206-207`）

三处都遵循同一结构：**先给一个具体的、可验证的细节（帽檐、缎带颜色、字的笔触），再让这个细节无法被第二次验证**。第二次访问时，物件"恢复正常"（`script.ts:219-222, 292-295`），于是玩家无法确定第一次是不是幻觉——这正是不可靠叙述该有的效果。

### 8.4 章节引言

每案开头一张卡，一句引言，且引言**只讲主题不讲情节**：

| 章 | 引言 | 出处 |
| --- | --- | --- |
| 序章 | 「所有伟大的画,都始于一抹不该出现的红。」 | `store.ts:468` |
| 第一案 | 「1888 年,秋。雾都的夜里,有人开始作画。」 | `chapters.ts:24`、`script.ts:61` |
| 第二案 | 「第二笔落下时,他已经开始收藏自己的作品了。」 | `chapters.ts:32`、`script2.ts:34` |

引言是"作者的旁白"，它提前告诉玩家这一案的核心隐喻（作画 / 收藏），玩家在游玩中会不断验证这句话。

### 8.5 道具描述里的暗线

线索描述（平均 70.6 字 / 第一案，78.7 字 / 第二案）承担了比对话更重的"解释"功能，因为它是**玩家自己点开看的**：

> 怀表：「它不该出现在这里——除非有人希望它被找到。」（`clues.ts:38`）
> 铜币：「这不是签名,这是**风格**——而风格是学出来的。」（`clues.ts:52`）
> 密码信：「第二件已确认收讫。构图较前作更为克制,进步显著。唯换行处仍有犹豫,望于第三件中克服。附:酬金依约。」（`clues.ts:137`）

第三条是最典型的"暗线"：一封信同时给出了三重信息——**有验收人、有评分标准、有报酬**。玩家读的时候以为在看证物，其实已经把整个故事的幕后结构读完了。

### 8.6 用少量文字立住人物（3 个例子）

**例 1 · 兔先生：用交易规则立人物**
> 「本店不收先令,只收秘密。而你带着一身好秘密,画家小姐。今晚,先赊给你。」（`script.ts:156`）

两句台词同时完成了：世界观（画里货币失效）、人物性格（商人、爱看戏）、玩法（白送道具要有理由）。后面那句「白色的兔子总是迟到,但你的表,停得刚刚好。」（`script.ts:167`）埋下怀表的伏笔，而主角的回应只有一个括号：「(表?……什么表?)」——用主角的无知反衬信息量。

**例 2 · 卡多什：用沉默立人物**
> 「四点四十五,我出后院。隔壁传来一声——『不要!』」（`script.ts:103`）
> 「这条街上,夜里的动静多了去了。醉汉、吵架、猫。我要是每一声都过去看,活不到今天。」（`script.ts:107`）
> 「姑娘,你也别用那种眼神看我。你要是也在这条街上住够十年,你就懂了。」（`script.ts:109`）

三句台词就写完了"伦敦东区的穷木匠"：他听见了、他没去、他知道自己该内疚、他用"住够十年"把内疚转成生存法则。而且这段证词在推理题里是**关键证据**——玩家必须一边厌恶他一边用他的证词破案。这种"证人的道德污点"，比任何背景描写都有效。

**例 3 · 克拉伦斯医生：用动机立人物**
> 「因为在你之前,我把同样的疑点报上去过三次。」
> 「第一次,被说成是"验尸官过度解读"。第二次,卷宗丢了。第三次——第三次,有人很客气地建议我,别再研究"构图"这种不属于医学的东西。」（`script2.ts:278-280`）
> 「所以我配合你,小姐。因为你是唯一一个,不需要我解释"为什么花被摆得那么整齐"的人。」（`script2.ts:282`）

医生活了整整两案才交代动机，而动机只有一条：**他被人压过，所以他要找一个不需要解释的同行**。一句话把"工具人 NPC"变成"体制受害者"，同时顺手把世界观扩了一层（有人在压案子）——这是全篇最经济的人物塑造。

**主角的塑造手法**：玛德蕾娜的所有性格都写在括号里（内心独白），且几乎不解释自己：

> 「…………换我来画他。」（`script.ts:208`，遇到超自然威胁的第一反应是**竞争心**）
> 「(体面。在她活着的时候没人给过她的东西,现在有了。)」（`script2.ts:292`，对死者的态度就是她的道德观）
> 「(不是威胁,不是警告。是请柬。这比刀子可怕多了。)」（`script2.ts:349`，恐惧的来源是"被理解"而不是"被威胁"）

## 9. 值得照学的 10 条

1. **把"章节"定义成一个可复算的预算**：每章 ≈ 150 条台词、3 张图、7-10 条线索、5 个核心线索、3 题推理、1 场 Boss。先定预算再写剧本，超了就砍，不会出现"某章突然变长"。

2. **核心线索必须"人 3 : 物 2"**，且每条只有一个来源、零门槛（不需要解谜就能拿到）。找线索的过程要好玩，但**不能有一处"我卡住了因为没找到"**。

3. **把"够不够推理"做成硬判定**：`CORE_CLUES[case].every(...)` 全齐才开推理板。玩家永远知道进度，不需要猜"还差什么"。

4. **集齐时自动弹一句独白 + 一条 toast**（"拼图齐了 / 按 R"），不要让玩家回去找 NPC 交任务。**该自动的事绝不手动化**。

5. **推理题只做 3 题，每题 3 选 1，诱饵必须是"玩家真会选的错答案"**，且错误反馈比选项长一倍——答错也是一次教学。用 `needClue` 在选项后面标出依据线索名，把"记忆负担"换成"判断负担"。

6. **推理完成后再开战**：先在独白里把结论说完整（200-330 字），再让反派承认、传送、震动、开打。战斗是叙事的转折动作，不是关卡考核。永远不要用战斗"打断"信息。

7. **Boss 的招式要抄推理结论**：第二案推出"有人替他看着钟"，Boss 就有「低语报时」「双拍」。招式的名字和文本是叙事的一部分，不是数值表的一部分。

8. **给探索一个可验证的战斗回报**：一个藏在阴沟里的隐藏线索（怀表）让 Boss 战永久预读意图。玩家会自己得出"多花 5 点理智是值得的"这个结论——**不要用文案告诉玩家该探索，用数值奖励说**。

9. **"看"本身要收费**：可调查点里有 18.9% 是"看了扣理智、什么也拿不到"的纯气氛点；「彩绘之眼」每 1.5 秒扣 1 点。让恐惧有价格，玩家才会在每次靠近时犹豫——犹豫就是恐怖。

10. **一处物件至少写三种状态**：没看告示板之前 / 第一案进行中 / 案破之后；拿到之前 / 拿到之后（实体消失）；第一次读 / 第二次读（文本否定第一次的恐惧）。用 `events.ts` 一个 `switch` 就能全部管理，成本极低但"世界活着"的体感极强。

## 10. 前半部分暴露的问题（客观）

1. **体量确实小**。前半部分 = 7 张图、2 场 Boss、17 条线索、6 道题、305 条台词、8255 字。按本作的对话速度（26ms/字 + 手动推进，每条 2-3 秒）估算，纯读对话约 12-15 分钟；加上走路、逐点调查、两场战斗与推理，实际游玩约 40-60 分钟。作为"范本"够用，作为"游戏"偏短。

2. **两案共用同一套节拍模板，第二遍就能猜到流程**：告示板 → 守门人 → 两个证人 → 现场医生 → 3 个物证 + 1 个眼睛点 → 集齐 → 3 题 → 独白 → Boss。第二案唯一的流程创新是"多开一张停尸间地图"，其余拍数与台词功能完全对应（见 §2.4）。

3. **Boss 骨架复用率高**：shade1 的 4 招里 3 招是共享骨架（claw / stare / charge），shade2 的 5 招里 3 招是共享骨架。真正属于各自 Boss 的只有 1-2 招（剖割 / 摹写 + 双拍）。狂化阈值两人都是 24，HP 只差 4。

4. **资源系统浅**：
   - 颜料 12 点只服务一个技能（猩红泼彩，−4/次），单场战斗最多用 3 次，探索中完全无用；
   - 体力只在战斗中下降，探索全程没有任何体力压力；
   - 理智虽然有 18 处消耗，但补给太多：6 个画架（+10 理智、补满颜料）、壁炉（+4）、兔子送药（每案 1-2 次）、章节切换（+30 理智 + 满体力 + 满颜料），实际很难被逼到低理智。

5. **推理没有失败态**：答错只 −5 理智，可无限重试；理智上限 100，等于允许答错 20 次。推理段因此只有"评价压力"（`flawless` 成就）而没有"生存压力"，与前面精心设计的理智系统脱节。

6. **第二案取消了所有选择点**（0 个 choice；序章与第一案合计 3 个）。第一案的"要不要凑近看"是全篇最好的恐惧交互，第二案全部改成"走过去就扣"，玩家的主动性下降。

7. **可调查点密度非常不均**：后院每 21.9 个可走格一个点，主街每 54.6 个；主街 21 个实体里 15 个是不可交互装饰，酒馆 22 个实体里 17 个是桌椅桶箱。这些装饰保证了画面丰富，但也制造了大量"看起来能点、其实点了没反应"的空转。

8. **重复访问文本占了实打实的篇幅**：两案共 24 段 After/Again 类脚本、35 条台词（305 条中的 11.5%），内容是"你已经看过了"的变体。它让世界更有礼貌，但不提供新信息——如果要做 10 章以上，这部分需要更省。

9. **世界被压成一条树**：7 张图全是一棵树，没有任何环路、没有捷径、没有"从 A 直接到 C"的可能。回访必须原路返回，第二案的停尸间尤其明显（汉伯里街 → 停尸间 → 汉伯里街 → 后院）。地图上的"自由"其实是走廊。

10. **文本密度偏高**：305 条台词 / 37 个可调查点 ≈ 每点 8.2 条。其中"证词类"NPC 单次交谈就 11-12 条（`docTalk2` 12 条、`longTalk` 11 条、`cadoschTalk` 11 条）。在解谜游戏里这个比例偏高——玩家的操作（点一下）与信息量（300 字）不成比例，第二次重玩时全部变成点击负担。可压缩到 8 条以内而不损失信息。

## 附：一句话总结

**一个关卡 = 一张地图（承担一种视角）× 一组可调查点（3 类：给线索 / 给代价 / 给气氛）× 一个硬闸门（5 条线索全齐）× 一次考试（3 题 3 选 1）× 一场被剧情解释过的战斗 × 一段把证据串成故事的独白。**

数据侧要定义：地图网格、实体（含 `interact` / `visionOnly` / `hideFlag`）、脚本（`line` / `choice` / `do`）、效果（`clue` / `san` / `flag` / `battle` / `teleport`）、线索表（`CORE_CLUES`）、题表（`DeductionQ`）、Boss 表（`EnemyDef`）。
体验侧要守住的只有一条：**每一段探索都必须让玩家多知道一件事，或者多付出一点代价；两者都没有的段落，就是可以删掉的段落。**
