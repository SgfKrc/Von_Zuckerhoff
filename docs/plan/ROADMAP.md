# 开发路线图

技术栈：React 18 + TypeScript + Vite + Canvas（纯网页，单文件 HTML 交付）
约定：内部分辨率 384×216，瓦片 16×16，全部地图与角色为代码内字符网格像素画

---

```
M0 设计文档        ← 当前阶段
M1 引擎骨架
```

## M1 · 引擎骨架

**目标**：把参考项目的骨架搬到新仓库，删掉所有不属于本作的机制。

| 任务 | 来源 | 处理 |
| --- | --- | --- |
| 主循环 / 输入 / 碰撞 / 相机 / 传送 | `engine.ts` | 直接复用 |
| 地图字符网格 + 实体 + 传送门 | `maps.ts` / `types.ts` | 复用，**扩展 struct 层** |
| 场景渲染（瓦片/实体/光照/雾） | `renderer.ts` | 复用；**新增图纸线框层** |
| 对话解释器（Step/Effect） | `store.ts` | 复用，**扩展 effect 类型**（图纸/糖/童话/对峙） |
| 像素美术管线（字符网格→ImageData） | `art/build.ts` | 直接复用 |
| 存档 / 成就 | `platform/localBackend.ts` + `ui/SaveScreen.tsx` + `ui/Achievements.tsx` | 复用；改 `vz.` 键名与新数据结构（SaveData v2 / RunMeta v2）；删 Electron IPC |
| 单文件打包 | `scripts/package-single-html.mjs` | 复用 |
| UI 覆盖层 | `ui/*.tsx` | 复用 DialogBox / HUD / SaveScreen / Toasts；**删掉** BattleUI / DeductionBoard / EvidenceBook，重写为 BlueprintUI / CodexUI / EncounterUI |

**删除清单**（明确不做）：理智 SAN、彩绘之眼、证物速写本、推理板、回合制战斗、成就的第二部映射、Electron 主进程。

**验收**：能在空白地图上走、能触发一段对话、能存档读档、能打包成单文件 HTML。

## M2 · 垂直切片（序章 + 第 1 章）

这是**唯一一次允许"做到好玩再继续"的检查点**。

**范围**

- 地图 7 张：糖堡站、雾中山路、古堡门厅、东翼走廊、卧室、餐厅、地窖入口
- 剧本：序章 + 第 1 章完整剧本（约 400–500 条对话）
- 系统：移动、调查、对话、选项、图纸（只读 + 1 次补图）、确信、糖、**存档（3 槽 + 自动）**、**成就（章节+解谜共 6 项）**、章节卡
- 谜题 3 个：
  1. **进门厅**：门厅的拱肋有一处画不出（图纸上的 `torn`），补对承重线才能让大门完全打开
  2. **夜游迷路**：走廊在图纸上是一段重复的循环——发现图纸上有两条不同的线，选对的那条通往卧室
  3. **地窖铁门**：铁十字门的锁是一个配重机关，需要量出三根梁的跨度才能配平
- 时长目标：60–90 分钟

**验收标准**

1. 新玩家不看任何说明，能在 10 分钟内理解"Tab 是图纸、图纸上有东西"。
2. 三个谜题中至少两个，玩家是**自己想出来**的（可测试：完成后能口头解释推理）。
3. 玩家在第 1 章结束时，能说出"这座城堡不太对劲"的至少两个具体证据。
4. 无卡死、无软锁。
5. 单文件 HTML 在 Chrome / Edge / Android Chrome 上可运行。

**做完这一关再决定是否继续投产。** 如果图纸机制不好玩，在这里改，成本最低。

## 分工建议

| 角色 | 负责 | 备注 |
| --- | --- | --- |
| 主设计（人） | 概念、系统规则、章节大纲、验收 | 所有"改设计"的决定权 |
| 编剧 agent | 按大纲写剧本数据（`scriptChN.ts`） | 必须给足原文行号与台词风格样例 |
| 关卡 agent | 按大纲画地图 + 配谜题 | 必须给 struct 层规范与地图校验脚本 |
| 美术 agent | 字符网格像素画 | 必须给调色板与精灵规格 |
| 程序（人/agent） | 引擎与系统实现 | 每个系统单独 PR |

**AI 协作纪律**（来自参考项目的教训）：

1. 剧本与关卡必须**先有文档、后写数据**，不允许"边写边想"。
2. 每个 agent 的任务必须带**验收标准**（例如"本章必须包含 4 个补图点、1 次对峙、1 次 revision"）。
3. 地图与剧本的改动后，跑一遍校验脚本（行等宽、传送点不在实体上、对话 id 全存在）。
4. 同一个系统只允许一个 agent 写，避免风格分裂。

## 风险登记

| 风险 | 概率 | 影响 | 应对 |
| --- | --- | --- | --- |
| 图纸谜题不好玩 | 中 | 高 | 垂直切片即验证；备选方案：把"补图"简化为"选对的结构符号" |
| 13 章跑不完 | 中 | 高 | 章节模板化；先做 6 章试玩版，再扩 |
| 童话 + 礼仪 + 魔药三系统叠加过重 | 中 | 中 | 每年只用 1–2 个系统做章；不是每章都要用满 |
| 首作全代码像素画产能不足 | 高 | 中 | 远景与立绘允许外部素材（已定）；地图瓦片建立可复用图集 |
| 文本量爆炸 | 高 | 中 | 单章对话条数硬上限 600；风味文本每条 ≤ 40 字 |
