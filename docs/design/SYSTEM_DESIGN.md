# 系统设计

本文档给出四大支柱与配套系统的**可执行规则**。程序按本文实现，关卡按本文配数据。

---

## 0. 资源与状态总表

主角状态全部是"数据"，不是"等级"。

| 状态 | 符号 | 范围 | 用途 | 恢复 |
| --- | --- | --- | --- | --- |
| 确信 | `conviction` | 0–100 | 驱动图纸；归零进入"否认"分支 | 签名、纹章仪式、艾玛的确认、完成一章 |
| 甜度 | `sweetness` | 0–100 | 糖的成瘾度；过高干扰图纸 | 随时间自然下降 |
| 糖 | `sugar` | 0–9 | 交易、镇静、提神、贿赂 | 探索、交易、厨房 |
| 墨水 | `ink` | 0–20 | 改写童话、补图 | 探索、交易 |
| 时段 | `phase` | 昼 / 暮 / 夜 | 决定可做的事 | 章节推进 |
| 位阶 | `rank` | 人类 → 恶魔九 → 恶魔八 / 魔女九 → 魔女七 | 能力与结局 | 不可逆 |
| 材料 | `mats{}` | 分项 | 炼药 | 一次性消耗 |
| 痕迹 | `traces{}` | 分项计数 | 记账：吃糖次数、服药次数、改写次数、失礼次数、看过的脸 | 只增不减 |

**关键**：`traces` 是终章结算用的账本。玩家在游戏里做的每一次"甜"、"改"、"变"，终章会被念出来。

## 1. 图纸系统

### 1.1 数据模型

每张地图的瓦片网格扩展为**三层**：

```ts
interface TileCell {
  art: string        // 现实层瓦片字符（视觉）
  struct: StructKind // 结构层类型（图纸层渲染依据）
  dir?: 0 | 1 | 2 | 3        // 朝向（梁/管道/滑轨需要）
  ratio?: number             // 传动比（齿轮）
  hidden?: boolean           // 现实层不可见，仅图纸层可见
}

type StructKind =
  | 'void'      // 空
  | 'floor'     // 可走地面
  | 'stone'     // 承重石墙
  | 'brick'     // 非承重砖墙（可拆）
  | 'fake'      // 假墙（现实层看起来是墙）
  | 'beam'      // 木梁
  | 'arch'      // 拱肋（承重点）
  | 'pipe'      // 管道（流）
  | 'rail'      // 滑轨
  | 'gear'      // 齿轮（有 ratio 与 dir）
  | 'weight'    // 配重
  | 'shaft'     // 竖井
  | 'stair'     // 楼梯
  | 'cavity'    // 夹层空腔
  | 'inkblot'   // 缺笔：画不出来的乱线（超自然标记）
  | 'torn'      // 缺页：整块空白
```

- 现实层用 `art` 渲染（`art` 可以留空，表示该格无可见物件）
- 图纸层忽略 `art`，只按 `struct` 画符号
- 碰撞仍按 `art` 所在瓦片的 `solid` 判定，**`struct` 不参与碰撞**——图纸是认知，不是碰撞体

### 1.2 图纸视图

按键 `Tab` 进入，`Tab`/`Esc` 退出。进入时：

1. 全屏压暗到 12%，播放 0.25 秒的"抽帧"过渡（现实层淡出，线框淡入）
2. 渲染线框层：`struct` → 符号 + 颜色

| struct | 符号 | 颜色 |
| --- | --- | --- |
| stone | 交叉剖面线 | `#8a8f96` |
| brick | 稀疏斜线 | `#5f6469` |
| fake | 剖面线 + 红叉 | `#8a5a5a` |
| beam | 双线 | `#a08a6a` |
| arch | 弧线 | `#c0b090` |
| pipe | 单线 + 箭头 | `#6a8a9a` |
| rail | 双点划线 | `#9a9a6a` |
| gear | 圆 + 齿 + 箭头 | `#c8a040` |
| weight | 矩形 + 下垂箭头 | `#7a7a8a` |
| cavity | 空心虚线框 | `#5a7a6a` |
| inkblot | 抖动乱线 | `#b04040`（闪烁） |
| torn | 空白 + 页角折痕 | `#e8e0d0` |

3. 图纸模式**不暂停世界**：雾照常飘、烛火照常闪、某些存在照常移动。这是恐怖来源——你在看图纸的时候，现实在动。

### 1.3 确信消耗

- 进入图纸：`conviction -2`
- 持续停留：每 10 秒 `-1`
- 补图操作：每次 `-5`（补错 `-8`）
- 确信 < 30：图纸出现**噪点**（随机格换成 inkblot 符号），玩家可能看错结构
- 确信 < 10：图纸只剩轮廓，无法读符号
- 确信 = 0：强制退出图纸，进入"否认"状态（见 1.7）

### 1.4 测量（标尺）

图纸模式下按住 `Shift` 拖拽，拉出一条测量线：

- 显示格数与**换算后的真实尺寸**（1 格 = 0.5 米，但城堡里某些区域比例不对——图纸会显示"比例异常"）
- 用于：判断桥的跨度、房间的实际面积、齿轮的直径、两根柱子的距离
- 测量结果记入"速写本"，可在后续谜题中引用

### 1.5 定位（圆规）

图纸模式下按 `C` 进入圆规：

- 点击两点 → 画圆 → 圆经过的格子上高亮 `arch` / `gear` / `fake`
- 用途：找对称轴（镜像暗门）、找转轴（圆形房间的圆心）、找等距点（配重要求对称）

### 1.6 补图（续线）——核心谜题形态

图纸上会出现**缺口**：某段传动/管路/滑轨中间缺一格或几格，以**虚线**表示。玩家要做的是把它连上。

**操作**：
1. 图纸模式 → 走到缺口附近 → 按 `E` 进入补图
2. 光标吸附到缺口端点，进入连线状态
3. 用方向键把线延伸出去，`E` 落笔，`Esc` 撤销整条线
4. 落笔瞬间**校验**：

**校验规则**（必须全部满足）：

| 规则 | 说明 |
| --- | --- |
| 同轴 | 线只能沿 `struct` 已存在的延伸方向走（管道接管道、滑轨接滑轨） |
| 连续 | 相邻格必须相邻（不能跳格） |
| 不穿承重 | 不能穿过 `stone` / `arch` |
| 转向合法 | 齿轮只能与相邻齿轮咬合；齿轮方向必须按 ratio 推得一致 |
| 闭合 | 两端都必须接到已有节点上（不许悬空） |
| 长度限制 | 受墨水限制：每格消耗 1 墨水 |

**结果**：
- 成功：现实中对应机关动作（门开、桥落、齿轮转、水流通）。屏幕先给**机械声**，再给**画面**——先听见，后看见。
- 失败：图纸上留下红色错线（永久，直到本章结束），确信 `-8`，机关不动或**反向动作**（可能触发陷阱）
- 错线可以擦除，但要花墨水 2 倍

**为什么这是本作的灵魂**：玩家不是在"找钥匙"，是在**断言一条结构关系**。世界的回应是物理的，不是叙事的。

### 1.7 图变（Revision）

每章结算时，图纸**自动更新**。更新规则：

- 地图数据里每个章节有 `revisions: RevisionPatch[]`，形如 `{ chapter, cells: [{x,y,struct}], note }`
- 进入新章时应用 patch，**不给任何提示**
- 玩家可以在速写本里对比"上次的图"，差异处标红
- 差异本身就是线索：多出来的通道是某人挖的，消失的梁说明有人拆过

**叙事用途**：第八章以后，城堡开始"自己改图"——`inkblot` 会蔓延，`torn` 会扩大。到终章，图纸会变成一张几乎看不清的废纸。这是主角认知崩溃的视觉化。

### 1.8 否认状态

`conviction = 0` 时：

- 强制退出图纸，屏幕变灰，全部 NPC 台词变为"你在自言自语"
- 玩家可以行动，但所有交互返回"这里没有东西"
- 持续 60 秒后进入 **BAD END · 弃婴**（他重新变回弗里茨·施密特，古堡消失）
- 恢复手段：吃糖（作弊式恢复，但 `traces.sugarCrisis++`，影响真结局）、找到艾玛

## 2. 序列魔药系统

### 2.1 位阶状态机

```
人类 ──恶魔九──> 恶魔 ──恶魔八──> 恶魔后嗣 ──(序列四不可达)──> ✕
  │
  └──魔女九──> 魔女 ──(序列八~六略)──> 魔女 ──魔女七──> 转化（男→女，不可逆）
```

- 位阶只可**上升**，不可下降、不可横跳（恶魔→魔女不可逆）
- 每次跃迁是一个**独立的过场**（服用场景）：独白、身体反应、艾玛的反应、图纸变化
- **可选的**：一周目不吃任何药也能通关（打到 NORMAL END），只是看不到真相层

### 2.2 完整配方表

材料名严格照原作，不改。

### 2.4 服用流程（过场规格）

每次服用是一次不可跳过的演出，约 90 秒：

1. **准备**：炼金台前，材料摆开，艾玛在场（她一定会出现）
2. **艾玛的一句话**：每个节点不同，永远是"陈述句"而非劝阻（例：「少爷，喝下去以后，您就不会再为这件事难过了。」）
3. **服用**：屏幕收到 384×216，只有主角的手与杯
4. **身体反应**：逐格变化的像素（眼睛变色、皮肤褪色、影子错位、呼吸节奏改变）
5. **图纸变化**：进入图纸模式，发现**图纸变了**——你看得见以前看不见的结构
6. **结算**：位阶更新，`traces.dose++`，结局树剪枝

### 2.5 副作用如何"机制化"

| 副作用 | 实现 |
| --- | --- |
| 情感淡漠 | 对话数据里给每个选项加 `requires: { empathy: true }`；`dev8` 后 `empathy=false`，这些选项**不出现在列表里**（不是灰掉，是消失） |
| 月光厌恶 | 地图标记 `moonlit: true` 的区域，进入时每 5 秒 `stamina -1`，画面偏绿 |
| 外貌变化 | 立绘换一套；某些 NPC 首次见面时触发专属台词 |
| 姓氏失效 | `wit7` 后，所有称呼从"少爷"变成"小姐"，族谱签名失效，终章继承判定归零 |

## 3. 童话系统

### 3.1 童话章数据

每章一则童话，存于 `data/tales.ts`：

```ts
interface Tale {
  chapter: number
  title: string          // 例：《三只铁皮鸟》
  pages: TalePage[]      // 每页：插图 + 文本
  words: TaleWord[]      // 可改写的词（每章 2-4 个）
  mirror: {              // 童话 → 现实的对应表
    tale: string         // 童话中的事物
    real: string         // 现实中的对应
    hint: string         // 玩家读懂后的提示（不直接给答案）
  }[]
}
```

### 3.2 阅读与读懂

- 在任意"可以坐下"的地方按 `E` 读童话（长椅、窗台、床上、墓地石阶）
- 童话以"书页"形式呈现：左页插图，右页文字
- **读懂判定**：读完后，`mirror` 中的对应关系会在速写本里留下"折角"（自动记录，但只记录玩家**已经遇到过**的现实事物）
- 读不懂不影响通关，但会错过提前知道结构的优势

### 3.3 童话层视图

图纸模式下按 `Q` 切换：

- 现实层淡出，画面上叠加一层**剪影/版画**风格的图层，只渲染 `mirror` 中提到的事物
- 此时玩家可以对比：现实里有但它没有的（多余之物）、它有但现实里没有的（缺失之物）
- 差额就是谜底
- **确信消耗加倍**（童话层比图纸层更伤）

### 3.4 词条改写

- 在书页上选中一个 `word`，输入替换词（从有限词库中选，不是自由输入）
- 消耗：`ink -3`，`traces.rewrite++`
- 现实立即改变：地形/事件/ NPC 行为
- **反噬**：被换掉的词会在后续章节的童话里重现，且出现在**不利于玩家**的位置。例：把"第三夜"改成"第一夜"，下一章的童话里就有一句"他在错误的夜里学会了数数"
- 每章最多改写 2 次（墨水限制 + 反噬惩罚）

### 3.5 洗掉的字

- 部分页的文本区被渲染成"水渍"，完全不可读
- 需要用纸面解谜（见 §5）还原
- 还原后，该页会永久保留内容（写进 `flags`）
- 还原内容 90% 是本章真相，10% 是**关于主角自己的**（这是关键设计：真相总是先伤到自己）

## 4. 糖与礼仪

### 4.1 糖的数值

| 行为 | sugar | sweetness | 备注 |
| --- | --- | --- | --- |
| 吃一块糖 | -1 | +15 | 可随时进行，0.5 秒动画 |
| 交易 | -1 | 0 | 换情报/材料/通行 |
| 贿赂 | -2 | +5 | 抵消一次失礼 |
| 提神（连续 2 块） | -2 | +30 | 移动与交互加速 30 秒 |
| 镇静 | -1 | +10 | 立即 `conviction +15` |

- `sweetness` 自然衰减：每 2 分钟 -1
- `sweetness ≥ 70`：进入"甜醉"——图纸随机噪点、坐标提示偏移、NPC 台词变甜变黏
- `sweetness ≥ 90` 且 5 分钟不补糖：戒断——`conviction` 每秒 -2，画面出现白色糖霜纹，必须再吃一块才能解除
- `traces.sugar` 记录总消耗，终章会结算

### 4.2 礼仪关卡

四种判定，都是**可操作的小博弈**，不是四选一。

#### (a) 座次（Arrangement）

- 界面：一条长桌，若干姓名牌，玩家拖拽
- 规则（照原作）：主人居中背对壁炉面向大门；女主人正对；客人按爵位向两侧排；教士优先于世俗贵族；同爵位按封地年限；年限相同按与皇室血缘亲疏
- 判定：排序完全正确得"体面"，错 1 处得"尚可"，错 2 处以上 `失礼+1`
- 限时：30 秒（老爷子的耐心）

#### (b) 称呼（Address）

- 界面：对话中出现一个头衔空缺，玩家从候选后缀中选
- 规则：公爵 Highness? 不——原作写的是敬语后缀，我们用：`阁下/大人/先生/夫人/小姐/神父/教授`，按爵位与身份对应
- 判定：即时反馈（NPC 的表情痣一顿）

#### (c) 舞步（Waltz）

- 界面：底部一条节拍轨道，四步一循环（前、侧、并、退），玩家按时序按方向键
- 原作彩蛋：踩脚。踩 1 次，艾玛说"您已经踩了"；踩 3 次，全场侧目
- 判定：准确率 ≥ 80% 得"体面"，< 50% 得 `失礼+2`
- **糖可以救场**：舞步失误时吃糖，被解释为"少爷血糖低"，不记失礼（这是糖在本作里最温柔的一次用途）

#### (d) 谈话（Conversation）

- 界面：正常对话框，但选项有"沉默"这个额外选项
- 规则：有些问题不能问（关于母亲、关于维多利亚、关于地窖）；正确的谦辞能换来情报
- 判定：问错一次 → 对方闭合，本章该 NPC 不再给情报（**不是失礼，是关门**）

### 4.3 失礼值

- 全篇累计 `traces.rude`
- 每章宴会：`rude` 达 3 → 被请出场，丢失本章支线与一条真相线索
- `rude` 达 8（全篇）→ 终章解锁一个额外对话："您从来就不属于这里"
- `rude` 不影响通关，只影响**你被这个世界接受的程度**

> **术语澄清**：「月时计」只是原作第十九章的**章名**，正文里没有这个词（全文检索仅 L6749 一处）。它的正文对应物是"凹槽里用光点与月光拼成的时钟"（L6921–L6953）。本项目不把它当设定术语，只作为这一件隐藏物品的开发代号。

**物品规格**

| 项 | 内容 |
| --- | --- |
| 名称 | 银色怀表（表壳内侧有干涸的血） |
| 获取 | 第三章 · 陵园 · 母亲墓碑下方的 `cavity`（图纸模式可见"不该存在的矩形"） |

**明确不做**

- 时间倒流
- 存档回滚
- 试错重来

（避免系统膨胀。任何"回溯"提案一律走 `ROADMAP.md` 的风险登记，不在本作范围内。）

## 6. 对峙系统

### 6.1 结构

```ts
interface Encounter {
  id: string
  name: string
  rules: string[]        // 规矩：必须遵守
  tell: string[]         // 征兆：每一回合前的提示
  weaknesses: Weakness[] // 破绽：用哪种支柱能打
  beats: number          // 回合数（钟声/呼吸/心跳）
  fail: FailEffect[]     // 每次违规的代价
}

interface Weakness {
  pillar: 'blueprint' | 'sequence' | 'tale' | 'sugar'
  action: string   // 玩家要做的操作
  reveal: string   // 成功后揭示的信息
}
```

### 6.2 流程

1. **登场**：一段影像 + 一句台词，`beats` 计数开始
2. **征兆**：每回合前给一个感官提示（声音/气味/温度/影子）
3. **应对**：玩家在限时内选一种支柱应对
   - 对：进入下一 beat，揭示一段信息
   - 错：`fail` 生效（不一定是伤害：可能是失去一段记忆、一个选项、一格图纸）
4. **破绽**：所有 beat 正确后，出现"破绽"窗口，玩家执行动作（补一条线 / 说一个名字 / 改一个词 / 递一块糖）
5. **收束**：无论成败都推进剧情，但**代价不同**

### 6.3 失败会不会 Game Over？

**不会。** 本作没有"死亡"。失败的结果是：

- 确信下降
- 失去真相碎片（该章的一页档案永久空白）
- 失去人性（`traces` 记一笔）
- 图纸被涂改（今后的解谜更难）

只有一种情况会中断：`conviction = 0` 的"否认"，且它是**一个结局**，不是失败屏。

### 6.4 四个示例

| 对峙 | 规矩 | 破绽 | 失败代价 |
| --- | --- | --- | --- |
| 无面石雕（第 4 章） | 不要看它的面部 | 图纸：找出"哪一尊有承重结构"（活的会压地） | 每看错一次，忘掉一段童年记忆（对话选项永久减少） |
| 拜亚基（第 8 章） | 听见它的名字时不要回头 | 童话：书里写过"回头的人"的结局 | 失去本章的童话页 |
| 千面之月（第 10/终章） | 回答，但不说真名 | 三颗宝石的名字 | 每错一次，一个对话选项消失 |
| 赫尔曼（终章） | 他从不主动攻击；他只回答问题 | 你问他"你的脸呢"，他才会露出破绽 | 问得越多，他越完整（他有更多的时间说话） |

### 6.5 梦游（夜间风险机制）

**原作依据**：主角常做梦，梦里的楼梯是倒的（L5964–L5966）；他多次"身体比意识先动"（L5079）；山路上他"深一脚浅一脚"却不停。

**触发**：每个「夜」时段结束时按概率判定：

```
p = 0.15 + (100 - conviction)/400 + sweetness/500
```

确信越低、甜度越高，越容易梦游。

**玩法**：

1. 画面转入"梦游层"：饱和度抽掉、边缘模糊、控件延迟
2. 玩家仍操控主角，但：
   - 方向键有 **120ms 延迟**
   - 约 **20% 的输入被抵消**（走一步停一步）
   - 视野只有 3 格半径
3. **危险点**：楼梯口、井、窗、断崖。踩空即触发结局「踩空」
4. **醒来方式**：
   - 长按 `E` 2 秒"念自己的名字"
   - 或走到艾玛／玛尔塔的声音处
5. **梦游的价值**：梦游时看见的是"真实的另一面"——箱子上的灰有手印、走廊尽头的长身人影、某扇门的位置和白天不同。这些是里线线索，醒着看不到

**设计意图**：把"睡觉"从"跳过时间"变成"风险与信息并存"的选择。玩家会开始怕夜晚。

**限制**：每章最多触发 2 次；第一次必定是教学关（不会真的踩空）。

## 7. 存档 / 周目 / 成就

> **复用决策**：整套存档与成就**直接复用参考项目的实现骨架**——`src/game/store.ts` 的 settle/applyEffects 内核、`src/platform/localBackend.ts`、`src/ui/SaveScreen.tsx`、`src/ui/Achievements.tsx`。参考项目已实测：8 手动槽 + 自动存档、localStorage/Electron 双层后端、JSON 导出导入、成就跨周目保存。本作不做桌面版，删掉 IPC 层即可（`localBackend.ts:196` 在 `window.localGameBackend` 不存在时自动回退 `browserBackend`）。

### 7.1 存档

**槽位**：8 个手动槽 + 1 个章节自动存档 + 1 个后日谈临时存档。

**键名**（统一前缀 `vz.`）：

| 键 | 内容 |
| --- | --- |
| `vz.save.slot0` … `vz.save.slot7` | 手动存档 |
| `vz.save.auto` | 章节开始时自动写入 |
| `vz.save.post` | 进入后日谈时写入（本次会话有效） |
| `vz.meta` | 跨周目资料（见 7.2） |
| `vz.achievements` | 成就解锁列表（跨存档、跨周目） |
| `vz.settings` | 闪烁、字号、震屏、音量 |

**存档点**：不做场景内的"画架式"存档物件，改用 **Esc → 存档页**（参考项目第二部的做法）。原因：本作古堡场景已经很密，再塞存档物件会破坏空间。

**数据结构**：

```ts
interface SaveData {
  version: 2
  savedAt: string
  chapter: number            // 0=序, 1..10, 11=终章, 12=番外
  phase: 'day' | 'dusk' | 'night'
  map: MapId
  x: number; y: number; dir: Dir
  conviction: number
  sweetness: number
  sugar: number
  ink: number
  rank: 'human' | 'dev9' | 'dev8' | 'wit9' | 'wit7'
  empathy: boolean
  mats: Partial<Record<MatId, number>>
  flags: Record<string, boolean | number>
  traces: Traces             // 只增不减的账本（糖/药/改写/失礼/看过的脸）
  seenTales: number[]
  releasedFaces: boolean     // 是否做过改良仪式
  gems: { ruby: boolean; emerald: boolean; diamond: boolean } | null  // 「三件事」读了哪张
  revisionsApplied: number[]
  encountersDone: string[]
}
```

**导出/导入**：单个 JSON，含 `game + meta + achievements`。纯网页的 localStorage 会被清，导出是唯一保险。

### 7.2 周目

```ts
interface RunMeta {
  version: 2
  completedRuns: number
  endingHistory: { ending: EndingId; at: string; run: number }[]
  unlockedInner: boolean
  seenTales: number[]
  seenPages: string[]
  watchBloodKnown: boolean
  achievements: string[]
}
```

- 任意结局通关 → `unlockedInner = true` → 标题画面出现「重读」
- **一周目的死亡结局同样解锁里线**——死得越莫名，越想知道为什么
- 二周目继承：`seenTales`、`seenPages`（可跳过重读）、`watchBloodKnown`
- 二周目不继承：数值、材料、位阶、糖

## 8. 数值平衡目标

| 指标 | 目标 |
| --- | --- |
| 单章时长 | 40–70 分钟 |
| 单章补图次数 | 3–6 次 |
| 单章对峙 | 1–2 次 |

| 一周目可达结局 | 5 种 |
| 真结局所需 | 三宝石线索齐 + 至少一次服药 + 终章选"不终结" |
