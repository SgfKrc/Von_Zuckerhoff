## 六、与参考项目的边界

`calabiyau-mdl` 的价值只在于两点：**引擎骨架**和**前半部分的关卡方法论**。

明确不继承：

1. 不继承「理智值 SAN + 彩绘之眼」——我们的认知机制是**工程师的图纸**。
2. 不继承「回合制命令战斗 + 元素弱点」——我们的对抗是**规则对峙**。
3. 不继承「线索板填空式推理」——我们的推理是**结构推断**（看图、算数、对位）。
4. 不继承后半部分的任何关卡、地图、剧本、数据表。

**引擎迁移的三个已知陷阱**（来自 `REF_ENGINE.md`）：

- `portraits.ts` 有跨项目 import（指向 `sequel/art/maddelena`），必须先断开再删 sequel
- 新增任何 UI 覆盖层必须同步改三处（`engine.ts:251`、`renderer.ts:230`、`engine.ts:75`），漏一处就出现"面板开着还能走"
- `Input.consume()` 不能写 `||`（短路会让按键滞留到下一帧）

## 八、从参考项目可迁移 / 不可迁移

`REF_LEVEL_DESIGN.md` 的实测统计（序章 + 第一案 + 第二案 = 305 条台词 / 8,255 字 / 7 张地图 / 115 个实体）是**预算基准**，不是设计模板。逐条判断如下。

### 可迁移

| 项 | 说明 | 本作用法 |
| --- | --- | --- |
| 9 段单章节拍 | S0 幕间 → S9 胜利独白；四成台词压在"矛盾证据 + 现场 + 取证圈"，转折独白只用 8–12 条却承担全部收束 | 见 `LEVEL_DESIGN §1.6` 的六段模板 |
| 线索三级结构 | 核心线索恒 5 条、来自 NPC 与现场 3:2；隐藏/真相线索**不参与判定**，只影响结局层级 | 直接沿用：真相碎片决定结局，不卡通关 |
| 地图密度规律 | 事件现场挤、过渡空间空；密度与黑暗同向 | `LEVEL_DESIGN §1.5` 的调查点密度表 |
| 文本长度硬指标 | 单条 ≤ 64 字（2 行）；NPC 单次 7–12 条 | 写入 `NARRATIVE_DESIGN §7` |
| flag 分支写法 | 同一物件在不同 flag 下的 5 种写法（可直接搬迁的 switch 模式） | 直接沿用 |
| 地图 hub 树 | 无环路，一张图做唯一 hub | 古堡以门厅为 hub |
| 回报模型 | 「隐藏线索兑换永久优势」 | 改造为「图纸碎片兑换对抗优势」 |

### 不可迁移（依赖已删除的系统）

- **「看要收费」**（彩绘之眼的理智税）—— 我们的图纸消耗的是确信，语义不同
- **Boss 抄推理结论** —— 我们没有推理板
- **证物本分组、推理板 3 选 1 题目形式** —— 我们的推理是排序、连线、测量
- **回合制战斗的招式/意图/资源表** —— 我们是对峙

### 体量提醒

参考项目完整第一部约 600–800 条台词（后三案未纳入统计）。本作 13 章合计约 **3,200 条**，单章 250 条上下——比参考项目单案高 1.5–2 倍，与章节长度（40–90 分钟 vs 45–60 分钟）成正比。这是可承受的上限，**不要再往上加**。
